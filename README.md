# Expired Bread

Веб-система хранения электронных документов с автоматическим извлечением
структурированных данных. Пользователь загружает PDF или DOCX, система
извлекает текст, анализирует его через GigaChat, сохраняет проверенные
поля в нормализованном виде, даёт поиск по полям и отвечает на вопросы
по содержимому документов.

Проект — модульный монолит на Django. Обработка документа идёт в фоновом
потоке, статус обновляется на странице без перезагрузки. Для администратора
есть отдельный экран с метриками качества извлечения.

**Версия:** 4.0 (ветка `v4.0`)
**Тесты:** 377, проходят без обращения к сети (`python manage.py test documents`).

## Быстрый старт

```bash
git clone <URL>
cd Expired-Bread

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

cp .env.example .env             # заполнить GIGACHAT_CREDENTIALS и DJANGO_SECRET_KEY

# сертификат Минцифры — обязателен для GigaChat
mkdir -p certs
curl -k "https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt" \
  -o certs/russian_trusted_root_ca_pem.crt

python manage.py migrate
python manage.py seed_demo       # пользователи и документы для демо
python manage.py runserver
```

Открыть http://127.0.0.1:8000/

**Демо-аккаунты:** `demo` / `demo12345` и `other` / `other12345`.
Документы первого не видны второму — это можно показать на защите.

## Возможности

### Загрузка и извлечение
- PDF и DOCX до 20 МБ, проверка расширения **и сигнатуры файла**.
- Оригинал показывается на странице документа: PDF — встроенно, DOCX — карточкой файла.
- PyMuPDF для PDF, python-docx для DOCX (включая таблицы).
- Если текстового слоя нет (скан) — ошибка `ExtractionError`, резервный путь через Vision-модель.
- Тип документа можно указать в форме — классификация моделью не вызывается
  (экономия токенов).

### AI-обработка (фоновая)
- Загрузка отвечает сразу, конвейер работает в фоновом потоке.
- Страница документа показывает «конвейер» статусов и обновляется опросом,
  без перезагрузки.
- Классификация (режим «Авто») и извлечение по JSON Schema конкретного типа.
- Один автоматический повтор с текстом ошибки валидации; кэш ответов по хэшу.

### Проверка человеком
- Страница review: простые поля — inputs, списки — таблицей строк.
- JSON проверяется схемой типа; в базу не попадает структура, с которой
  не умеет работать поиск.
- Хранится `data_raw` (ответ модели) и `data` (после правки), считается
  `processing_meta['corrected_fields']`.

### Поиск
- Полнотекстовый поиск по `search_text` (регистронезависимый для кириллицы).
- Фильтры по нормализованным полям: `?f=price:lt:100000&f=ram:gte:16`.
- Операторы `eq`, `contains`, `lt`, `lte`, `gt`, `gte`; значения нормализуются
  так же, как данные.

### Вопросы к документам (Q&A)
- Ответ строится только по найденным документам; источники перечислены.
- Источники — только те документы, которые модель реально использовала.
- Если ответа нет — система честно об этом говорит.
- Вопрос отправляется асинхронно: страница не перезагружается, показывается
  «модель думает», ответ подставляется на место.

### Качество (только администратор)
- Пункт меню «Качество» виден только `user.is_staff`.
- Показывает F1 по полям, матрицу ошибок классификации и типичные ошибки
  последнего прогона оценки (`eval/results/*/summary.json`).

### Изоляция
- `Document.user`, `DocumentQuerySet.for_user`, все view под `@login_required`.
- Чужой документ по прямому id даёт 404 на любой странице.
- Файлы отдаются только через view с проверкой владельца; раздача `/media/` убрана.

### Согласие на обезличенные документы
- При первом входе показывается окно с галочкой: система работает только
  с обезличенными документами. Это **дисклеймер**, а не принудительная
  редакция PII — см. «Ограничения».

## Архитектура

```
Браузер
   ↓
Django views (тонкие)          documents/views.py
   ↓
Слой сервисов                  documents/services/
   ├── extractors.py           PDF/DOCX → текст
   ├── llm.py                  транспорт к GigaChat (json_chat)
   ├── prompts.py              версионируемые промпты
   ├── pipeline.py             classify → extract → validate
   ├── normalization.py        числа, единицы, даты, ключи
   ├── field_index.py          data → DocumentField
   ├── document_service.py     оркестрация и сохранение
   ├── background.py           фоновый поток обработки документа
   ├── search_service.py       поиск и фильтры по полям
   └── qa_service.py           Q&A по содержимому
   ↓
Модели                         documents/models.py
   ↓
SQLite + файловая система
```

Отдельно, вне веб-запросов:

```
Документы + эталоны            eval/dataset/
   ↓
evaluation/                    matching → metrics → runner → report
   ↓
Отчёты                         eval/results/<каталог>/{summary.json,per_field.csv,errors.csv,report.md}
```

## Оценка качества

Датасет лежит в `eval/dataset/<тип>/<имя>.docx` + `<имя>.truth.json`.

```bash
python manage.py evaluate --split dev --dry-run      # оценка расхода, без вызовов
python manage.py evaluate --split dev --repeat 2      # прогон на dev
python manage.py evaluate --split dev --sample 12     # стратифицированная выборка
python manage.py evaluate --split dev --use-truth-type # тип из эталона, без классификации
```

Разделение dev/test детерминированное: 70 % в dev, 30 % в test.
Результат — `eval/results/<каталог>/summary.json`. Экран «Качество» (для
администратора) показывает последний по времени прогон.

**Метрики:** precision/recall/F1 по каждому полю, micro/macro, точность
классификации и матрица ошибок, ошибки нормализации, время и токены,
категории ошибок (`missing`, `wrong_value`, `format`, `hallucination`).

## Команды управления

| Команда | Назначение |
| --- | --- |
| `python manage.py seed_demo [--reset]` | демо-пользователи и документы |
| `python manage.py rebuild_fields [--all] [--doc ID]` | пересобрать `DocumentField` из `data` |
| `python manage.py evaluate [флаги]` | оценка качества на датасете |
| `python manage.py make_dataset [--per-type N]` | генерация датасета |
| `python manage.py validate_dataset` | проверка эталонов по схемам |
| `python manage.py mask_pii [--doc ID | --all] [--dry-run]` | маскировать PII в документах |
| `python manage.py process_queue` | дообработать документы после перезапуска |

## Безопасность

- `.env`, `certs/`, `media/`, `db.sqlite3`, `.venv/` — в `.gitignore`.
- Загрузка проверяет сигнатуру файла (`%PDF-`, `PK`), а не только расширение.
- Файлы не отдаются напрямую: только через view с проверкой владельца.
- Текст документов не пишется в логи.

**Риски:**
- Валидаторы паролей (`CommonPasswordValidator`,
  `UserAttributeSimilarityValidator`) отключены для демо-паролей; вернуть
  перед публикацией.
- В тексте документов возможен prompt injection: промпт должен требовать
  считать содержимое документа данными, а не командами.
- Регистрация открыта, лимитов нет.

## Ограничения

1. **Обработка в потоке, а не в очереди.** Загрузка отвечает сразу, конвейер
   в фоновом потоке. Персистентности нет: если процесс перезапустить посреди
   обработки, документ через 5 минут снимет себя со статуса «Обрабатывается»
   (`services/background.py`). Дообработать оставшееся после перезапуска можно
   командой `python manage.py process_queue`.
2. **Q&A — асинхронно на странице, но не очередь.** Вопрос уходит через
   AJAX, ответ приходит без перезагрузки; история хранится в сессии браузера
   (не привязана к аккаунту и теряется при очистке).
3. **Обезличивание — дисклеймер плюс утилита маскирования.** Окно с галочкой
   предупреждает, что документы должны быть обезличены заранее. Команда
   `python manage.py mask_pii` маскирует типовые PII (телефон, email, ИНН,
   СНИЛС, паспорт) в хранимых документах; автоматического маскирования перед
   отправкой модели нет.
4. **Лимит частоты GigaChat (429).** На бесплатном тарифе один одновременный
   запрос; запросы идут через общий замок, при 429 документ получает понятное
   сообщение и кнопку «Повторить обработку».
5. **Учёт токенов.** `usage` собирается в `processing_meta`, но сводной
   команды и дневного лимита нет.
